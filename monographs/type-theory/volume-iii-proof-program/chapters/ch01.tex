\chapter{A Proof That Runs}
\label{ch:proof-that-runs}

A proof and a program can look unrelated when they are written in their usual surface languages. A proof may be a tree of assumptions and inference rules. A program may be a term with variables, binders, and applications. The first purpose of this volume is to remove the accidental difference without erasing the real one.

Consider the elementary logical task
\[
  P\to Q,\qquad Q\to R,\qquad P \quad\vdash\quad R.
\]
A natural-deduction proof applies the first implication to the evidence for $P$, obtaining evidence for $Q$, and then applies the second implication. A typed program does exactly the same thing: if $f:P\to Q$, $g:Q\to R$, and $x:P$, then $g\,(f\,x):R$.

This is not yet a theorem about every logic and every programming language. It is an exact statement about the rules we now choose.

\begin{principle}
The Curry--Howard correspondence begins only after the logical calculus and the term calculus have been fixed. The slogan comes after the rule map, not before it.
\end{principle}

\section{The smallest useful core}

The primary calculus of this volume is $\mathrm{CH}\text{-}0$. Its first tranche uses only implication. Types are generated by
\[
 A,B ::= P \mid A\to B,
\]
where $P$ ranges over atomic types. Terms are
\[
 t,u ::= x \mid \lambda x{:}A.t \mid t\,u.
\]
A context $\Gamma$ is a finite list of variable declarations $x{:}A$. The term judgment
\[
 \Gamma\vdash t:A
\]
means that $t$ has type $A$ under assumptions $\Gamma$.

For the logical presentation we also write $\Gamma\vdash A$ when the proof term is being suppressed. The suppression is not proof irrelevance; it merely hides the selected witness from the notation.

\begin{formal}[title={Formal Interlude: implication rules}]
The implication fragment has the following rules.
\[
\frac{}{\Gamma,x{:}A\vdash x:A}\;\textsc{Var}
\qquad
\frac{\Gamma,x{:}A\vdash t:B}{\Gamma\vdash \lambda x{:}A.t:A\to B}\;\to I
\]
\[
\frac{\Gamma\vdash f:A\to B\qquad \Gamma\vdash a:A}{\Gamma\vdash f\,a:B}\;\to E.
\]
The logical natural-deduction rules have the same introduction/elimination shape when the proof term is omitted. Assumption discharge in $\to I$ is represented by lexical binding in $\lambda x{:}A.t$; implication elimination is represented by application.
\end{formal}

Plate~\ref{plate:two-presentations} places these two presentations side by side. The point is not visual similarity. The point is that the premises and conclusion of each logical rule determine the constructor or eliminator of the assigned proof term.

\section{Term assignment rather than metaphysical identity}

Let $D$ be a natural-deduction derivation in the implication fragment. We write $\assign{D}$ for its assigned proof term. The assignment is defined recursively:

\begin{itemize}
\item an open assumption labeled $x{:}A$ is assigned the variable $x$;
\item implication introduction discharging $x{:}A$ is assigned $\lambda x{:}A.\assign{D}$;
\item implication elimination of proofs assigned $f$ and $a$ is assigned $f\,a$.
\end{itemize}

\begin{proposition}[Rule-level term assignment]
\label{prop:rule-term-assignment}
If $D$ is a well-formed implication-only natural-deduction derivation of $A$ from assumptions represented by $\Gamma$, then the recursively assigned term satisfies
\[
 \Gamma\vdash \assign{D}:A.
\]
\end{proposition}

\begin{proof}
Induct on the final rule of $D$. If the final rule is an assumption, the result is exactly \textsc{Var}. If it is implication introduction, the induction hypothesis gives the typing judgment for the immediate subderivation under the discharged assumption; rule $\to I$ produces the required abstraction. If it is implication elimination, the two induction hypotheses type the function evidence and argument evidence; rule $\to E$ types their application. These are all cases of the implication fragment.
\end{proof}

The converse reconstruction is equally direct for this syntax: erase the term constructors into the corresponding introduction/elimination rules while preserving variable labels and types. There can still be administrative differences in how a human writes a derivation, so the volume speaks of a correspondence under a fixed representation rather than claiming that ink on a proof page is literally executable machine code.

\begin{warningbox}
\textbf{Do not confuse propositions-as-types with the claim that every type is merely a truth value.} In $\mathrm{CH}\text{-}0$, the same type-forming structure supports a logical reading and a computational reading. Data-bearing types may preserve distinctions that a proof-irrelevant semantics would quotient away. Later chapters make that pressure explicit.
\end{warningbox}

\section{The composition proof is function composition}

The formula
\[
 (Q\to R)\to(P\to Q)\to(P\to R)
\]
has the proof term
\[
 \lambda f{:}(Q\to R).\lambda g{:}(P\to Q).\lambda x{:}P. f\,(g\,x).
\]
Read from the outside inward, the term says exactly what the proof says. Assume a proof/program $f$ taking $Q$ evidence to $R$ evidence. Assume one taking $P$ evidence to $Q$ evidence. Assume $P$. Apply $g$, then $f$. Discharge the assumptions in reverse order.

\begin{workedexample}[title={Worked Example: composition as a proof object}]
Let
\[
 c=\lambda f{:}(Q\to R).\lambda g{:}(P\to Q).\lambda x{:}P.f\,(g\,x).
\]
We can infer its type from the innermost application outward:
\[
 x:P,\;g:P\to Q \vdash g\,x:Q,
\]
\[
 x:P,\;g:P\to Q,\;f:Q\to R \vdash f\,(g\,x):R.
\]
Three implication introductions then discharge $x$, $g$, and $f$. Thus
\[
 \vdash c:(Q\to R)\to(P\to Q)\to(P\to R).
\]
No separate executable artifact has been smuggled in. The proof term itself is the typed composition program in this calculus.
\end{workedexample}

\section{A first structural theorem: weakening}

A proof can ignore an available assumption. A program can have an unused variable in its typing environment. These are the same structural permission at the level of $\mathrm{CH}\text{-}0$ typing.

\begin{theorem}[Weakening for the implication fragment]
\label{thm:weakening-imp}
If $\Gamma\vdash t:A$ and $y\notin\mathrm{dom}(\Gamma)$, then
\[
 \Gamma,y{:}B\vdash t:A.
\]
\end{theorem}

\begin{proof}
Induct on the typing derivation of $\Gamma\vdash t:A$.

For \textsc{Var}, the variable typed in $\Gamma$ remains available in the extended context. For $\to I$, alpha-rename the bound variable if necessary so that it differs from $y$. Apply the induction hypothesis to the premise under the extended context, then reapply $\to I$. For $\to E$, apply the induction hypothesis to both premises and reapply application typing. No other typing rules occur in the implication fragment.
\end{proof}

This proof matters because later substitution and preservation arguments depend on the discipline of contexts. The theorem is elementary, but its shape repeats throughout type theory: structural properties are not background magic; they are the infrastructure that makes local proof transformations legal.

\section{The checker as an executable microscope}

The first laboratory implements exactly the implication fragment just defined. Its surface syntax is intentionally austere:

\begin{verbatim}
Type: (-> P Q)
Term: (lam x P x)
Term: (app f a)
\end{verbatim}

The checker parses these S-expressions, reconstructs types, and rejects mismatched applications or unbound variables. It is small enough that the reader can audit the entire trusted algorithm.

\begin{labbox}
Run \texttt{labs/lab01\_implication\_checker.py}. The retained fixture set checks identity, the K combinator, composition, a wrong argument type, and an unbound variable. The laboratory establishes only that this implementation behaves as recorded on these fixtures. The typing theorems remain mathematical obligations.
\end{labbox}

A successful run produces machine-readable JSON. The negative fixtures are as important as the positive ones: an implementation that accepts every term is not evidence for a type system.

\section{What has actually been established}

At this point the exact result is narrow and strong:

\begin{itemize}
\item $\mathrm{CH}\text{-}0$ implication proofs admit a recursive term assignment.
\item The assigned terms are well typed by Proposition~\ref{prop:rule-term-assignment}.
\item Assumption discharge and abstraction are aligned by rule shape.
\item Implication elimination and application are aligned by rule shape.
\item Weakening holds for the implication fragment.
\item A small checker executes the same typing rules on retained examples.
\end{itemize}

We have not yet shown that proof simplification is computation. That requires a dynamic statement: when a proof contains an introduction immediately consumed by an elimination, what happens to the proof term? Chapter~\ref{ch:detours-compute} answers that question.

\item \textbf{Checkpoint.} Give the $\mathrm{CH}\text{-}0$ type of $\lambda x{:}P.x$.
\item \textbf{Checkpoint.} Which typing rule corresponds to implication elimination? State both premises.
\item \textbf{Checkpoint.} Explain why $\Gamma\vdash A$ suppresses information relative to $\Gamma\vdash t:A$ without assuming proof irrelevance.
\item \textbf{Core.} Derive $P\to(Q\to P)$ and write its proof term.
\item \textbf{Core.} Derive $(P\to Q)\to((Q\to R)\to(P\to R))$ and compare the term with ordinary function composition.
\item \textbf{Core.} In context $f:P\to Q, g:Q\to R, x:P$, type every proper subterm of $g\,(f\,x)$.
\item \textbf{Synthesis.} Give one precise sense in which implication introduction and lambda abstraction are “the same structure,” and one sense in which the written proof and written program remain different artifacts.
\item \textbf{Synthesis.} Why is “every type is a proposition” stronger than the correspondence established in this chapter?
\item \textbf{Proof Workshop.} Prove weakening for the implication fragment, explicitly handling the binder-renaming condition in the $\to I$ case.
\item \textbf{Proof Workshop.} Prove Proposition~\ref{prop:rule-term-assignment} by induction on the final natural-deduction rule and state why the induction is exhaustive.
\item \textbf{Design Clinic.} Extend the laboratory syntax with a human-readable arrow type parser while preserving the simple internal AST. State two malformed inputs that must still be rejected.
\item \textbf{Challenge.} Define a size measure on implication derivations and on assigned proof terms. Investigate which choices make rule-by-rule term assignment size-preserving and which introduce constant administrative overhead. State your metric before comparing sizes.
\end{enumerate}
