\chapter{A Program With Someone on the Other End}

\section*{1.1}
\[
  \send{\Nat}{\recv{\Bool}{\mathsf{end!}}}.
\]
The sequence is read from the local endpoint's perspective: send a natural, receive a Boolean, then actively close.

\section*{1.2}
They permit different first actions. In the first type the endpoint must send a natural before it can receive. In the second it must receive a Boolean before it can send. Because protocol state records order, the two types are not interchangeable.

\section*{1.3}
$\Gamma$ is the reusable value-variable context. $\Delta$ is the linear channel/session environment whose bindings record communication obligations that must be distributed and consumed according to the process typing rules.

\section*{1.4}
One valid skeleton is
\[
  x!\chanval{b}.x!\chanval{n}.\mathsf{close}\;x.0,
\]
with $b:\Bool$ and $n:\Nat$ in $\Gamma$, under an endpoint binding $x:\send{\Bool}{\send{\Nat}{\mathsf{end!}}}$ in $\Delta$.

\section*{1.5}
A valid local action trace is
\[
  \mathsf{recv{:}Nat},\quad \mathsf{recv{:}Bool},\quad \mathsf{wait}.
\]
The final action is passive wait because the endpoint type ends with $\mathsf{end?}$.

\section*{1.6}
Wrong order: $\mathsf{recv{:}Bool},\mathsf{send{:}Nat},\mathsf{close}$. Wrong payload: $\mathsf{send{:}Bool},\mathsf{recv{:}Bool},\mathsf{close}$. Either violates the constructor at the current protocol frontier.

\section*{1.7}
The function type $\Nat\to\Bool$ says that application to a natural produces a Boolean result under the function semantics; it does not state a two-party communication order. The session type says that the local endpoint must send a natural, later receive a Boolean, then close; it does not by itself define a mathematical function from naturals to Booleans or require the returned Boolean to be functionally determined by the sent natural.

\section*{1.8}
A deterministic checker can choose one concrete finite trace representation and decide whether that trace follows a finite session description. This is executable evidence about those fixtures. The mathematical process relation can still permit several independent enabled communications, so the checker does not redefine that relation as deterministic.

\section*{1.9}
For the Gate-1 syntax, inspect the outer constructor. A type beginning $!A.S$ has first action send; one beginning $?A.S$ has first action receive; $\mathsf{end!}$ has first terminal action close; $\mathsf{end?}$ has first terminal action wait. These cases exhaust the grammar. Hence every finite Gate-1 session has exactly one first local action class.

\section*{1.10}
Use structural induction with one case for each constructor:
\[
\frac{\mathcal P(S)}{\mathcal P(!A.S)},\qquad
\frac{\mathcal P(S)}{\mathcal P(?A.S)},\qquad
\mathcal P(\mathsf{end!}),\qquad
\mathcal P(\mathsf{end?}).
\]
Define $|S|$ as one plus the continuation length for send/receive and as $1$ for either terminal constructor. A complete trace consumes exactly the outer constructor and then a complete trace of the continuation. The induction hypothesis gives the continuation count, so the total is $1+|S'|=|S|$. The terminal cases consume one terminal action and have length one.

\section*{1.11}
Add a refinement/predicate layer, for example $!\{n:\Nat\mid n>0\}.S$, or keep the session type unchanged and attach a runtime/static predicate obligation to the payload action. The new checker must verify both the ordinary payload type and the predicate. This is a refinement or contract layer; ordinary Gate-1 session fidelity continues to enforce only the payload type/order represented by the session syntax.

\section*{1.12}
An intentionally persistent service may be correct precisely because it continues accepting requests rather than reducing to a final value. Gate 1 is finite and nonrecursive, so the example requires at least a guarded recursive session type such as $\mu t.?\mathsf{Req}.!\mathsf{Resp}.t$ together with process recursion and an operational semantics for unfolding. Productivity, fairness, or response guarantees require additional hypotheses/results beyond guarded syntax alone.

\chapter{Two Ends of One Obligation}

\section*{2.1}
\[
  \dual{\send{\Nat}{\recv{\Bool}{\mathsf{end!}}}}
  = \recv{\Nat}{\send{\Bool}{\mathsf{end?}}}.
\]

\section*{2.2}
$\dual{\mathsf{end!}}=\mathsf{end?}$. Distinguishing active close from passive wait records which peer performs the final action and which observes it. A single undirected terminal constructor would erase that local obligation from this teaching calculus.

\section*{2.3}
Session duality is a syntax-directed operation that exchanges complementary communication actions on paired endpoints; logical negation is a logical connective or derived operation whose meaning depends on a logic and is not identified with session duality here.

\section*{2.4}
If the client receives a Boolean, then sends a natural, then waits, the client endpoint has
\[
  ?\Bool.!\Nat.\mathsf{end?},
\]
and the peer has its dual
\[
  !\Bool.?\Nat.\mathsf{end!}.
\]

\section*{2.5}
The principal synchronous reduction is
\[
(\nu x\,y)(x!\chanval{7}.P\mid y?(n).Q)
\longrightarrow
(\nu x\,y)(P\mid Q[7/n]).
\]
The corresponding endpoint session states advance by one dual send/receive constructor.

\section*{2.6}
$\Delta_1\uplus\Delta_2$ denotes a disjoint union. The side condition prevents the same linear endpoint binding from appearing in both premises. Ordinary union would not by itself record or enforce that separation and would therefore permit an obligation to be duplicated across parallel subprocesses.

\section*{2.7}
Dual endpoints guarantee complementary local actions when those peers meet at the relevant session frontier. A process may nevertheless hold two sessions and wait first on session $b$, while its peer waits first on session $a$. Each local session can be well typed, yet neither process reaches the send action the other is awaiting. Thus duality/fidelity is local; network deadlock freedom is stronger.

\section*{2.8}
A linear variable discipline must be connected to runtime identity by implementation assumptions. Examples include: (i) compilation preserves endpoint identity and does not introduce aliases that bypass the type system; (ii) the runtime/API prevents hidden duplication or sharing of the underlying socket/handle; (iii) foreign-function or serialization boundaries preserve the ownership discipline. Any two appropriately stated assumptions earn full credit.

\section*{2.9}
Proceed by structural induction on $S$.

If $S=!A.S'$, then
\[
\dual{\dual S}=\dual{?A.\dual{S'}}=!A.\dual{\dual{S'}}=!A.S'
\]
by the induction hypothesis. The receive case is symmetric. For $\mathsf{end!}$,
$\dual{\dual{\mathsf{end!}}}=\dual{\mathsf{end?}}=\mathsf{end!}$; the $\mathsf{end?}$ case is symmetric. Hence finite Gate-1 duality is involutive.

\section*{2.10}
Let each binding of finite $\Delta$ be assigned to exactly one of $\Delta_1$ or $\Delta_2$. No binding can therefore occur in both, so their domains are disjoint. Every binding occurs in one of them, so the disjoint union contains every binding of $\Delta$. No other bindings were introduced, hence $\Delta=\Delta_1\uplus\Delta_2$. This is the finite set/map invariant used by the parallel typing rule.

\section*{2.11}
A useful diagnostic reports the earliest structural disagreement and classifies it. For example: `direction mismatch at step 1: expected recv, peer offers recv`; `payload mismatch at step 2: Nat versus Bool`; `premature termination: peer is wait while local continuation requires send Bool`. Separate classes tell the reader which invariant failed and preserve evidence useful for repair and testing. A generic mismatch message discards that distinction.

\section*{2.12}
Use two sessions $a$ and $b$. Give $P$ an endpoint that must eventually send on $a$ and another that first receives on $b$; give $Q$ the dual endpoints, but let $Q$ first receive on $a$ before it reaches its send on $b$. Schematically:
\[
P = b?(u).\,a!\chanval{v}.P',\qquad
Q = a?(v).\,b!\chanval{u}.Q'.
\]
Each session endpoint pair can carry dual local types. Initially, however, $P$ waits for $Q$ on $b$ while $Q$ waits for $P$ on $a$, so the wait-for relation contains the cycle $P\to Q\to P$ and no communication is enabled. Global deadlock freedom/progress fails. Local session compatibility and the absence of a send/receive type mismatch can remain intact.
