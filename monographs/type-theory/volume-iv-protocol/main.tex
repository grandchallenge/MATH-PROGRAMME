\chapter*{Scope and series thesis}
The phrase ``grand unified theory'' names a research thesis, not an established theorem.
This volume asks what changes when the primary computational object is interaction rather than
closed function evaluation.

The core positive result is deliberately scoped. Finite synchronous binary session typing can
track complementary communication obligations through reduction, yielding subject reduction,
communication safety, and a narrow single-session progress theorem. The volume then changes the
model on purpose: multiple sessions expose a typed deadlock; guarded recursion exposes the
difference between well-formed recurrence and productivity; asynchronous queues change the state
space; global descriptions add multiparty structure; subtyping adds replacement; monitors add an
observation boundary; faults and effects expose obligations not contained in local protocol state.

No chapter establishes arbitrary deadlock freedom, fairness, fault tolerance, security,
scheduler independence, correctness of real network transports, or application-level correctness
merely from session fidelity.

\chapter*{How to read the formalism}
A session type is an ordered communication obligation. A process judgment
\[
  \ptypes{\Gamma}{\Delta}{P}
\]
separates reusable value assumptions in \(\Gamma\) from linear channel obligations in
\(\Delta\). The process step \(P\to P'\), protocol-environment step
\(\Delta\envstep\Delta'\), process structural congruence \(P\pcong Q\), and later
asynchronous queue transitions are distinct semantic relations.

The volume uses several named calculi rather than silently changing one calculus under the reader:
\texttt{PROTO-0} (finite synchronous binary core), \texttt{PROTO-N1} (multi-session network
extension), \texttt{PROTO-R1} (guarded recursion), \texttt{PROTO-A1} (explicit FIFO queues),
\texttt{PROTO-M1} (bounded multiparty comparison), \texttt{PROTO-S1} (bounded synchronous
subtyping), and \texttt{PROTO-MON1} (finite runtime monitoring).

\chapter*{Historical orientation}
The process-calculus background includes Hoare's CSP tradition \cite{hoare1978}, Milner's CCS
\cite{milner1980}, and the later \(\pi\)-calculus development of Milner, Parrow, and Walker
\cite{milner1992}. The session-type line used here begins with exact, calculus-specific work such
as Honda's dyadic interaction types \cite{honda1993} and the structured communication discipline
of Honda, Vasconcelos, and Kubo \cite{honda1998}. Linear logic \cite{girard1987} supplies an
important proof-theoretic lineage, but Chapter 13 keeps proof/process correspondences
calculus-specific.

\chapter*{What Volume IV established}
Within the exact finite fragments stated in the theorem audit, the composition develops and
internally proves or checks: finite duality involution; linear environment splitting; payload
substitution; principal redex compatibility; finite synchronous subject reduction and
communication safety; narrow one-session progress; a well-typed multi-session deadlock witness;
guarded unfolding and one-step recursive preservation; bounded FIFO queue invariants and
asynchronous fidelity; finite per-exemplar multiparty projection checks; bounded synchronous
session subtyping safety; finite monitor soundness; and selected structural-congruence typing.

The negative results are equally important. Local session typing does not imply unrestricted
global progress, fault tolerance, fairness, security, or application correctness. Recursive
well-formedness does not imply productivity. Synchronous and asynchronous semantics are not
declared universally equivalent. General multiparty projection and general asynchronous
subtyping remain literature-dependent or outside scope.

\chapter*{Transition to Volume V}
Protocol state becomes insufficient when an event changes or observes state not owned by the
session frontier: a database, file, device, capability, exception state, random source, or other
environmental object. The next volume therefore asks:

\begin{quote}
\textbf{Once communication is typed, how do we type the events by which computation changes or
observes a world not reducible to the protocol itself?}
\end{quote}

That is the forced transition to Volume V --- \emph{EFFECTS: Computation Meets the World}.
