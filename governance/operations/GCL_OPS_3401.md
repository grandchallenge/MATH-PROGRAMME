Actual GH-OS run `43857375039` dispatched **15 PRs, 16 API calls, 22.772 s**; `43858364050` dispatched **14 PRs, 15 API calls, 20.733 s**; `43855516068` dispatched **15 PRs, 16 API calls, 21.497 s**. The resulting controllers can retry the same unresolved identity 5 times. These are measured dispatch costs, not full installation budget charges (prequeue uses workflow token rather than the same App installation).

## Protected correction in ordinary PR

The external intake controller `ci/ns_ci_intake_pr_controller.py` currently refreshes a protected queue manifest, branch and PR lists, and probes each queue binding not found through the listings with an additional `GET contents` request. The MATHSOLVE protected manifest has **20 bindings**; the GitHub matching-ref response has **31 intake refs**, and **none** of the 20 bound branch names appears in it. The former logic therefore attempts 20 redundant negative contents reads per run. The ten-minute scheduled controller may incur these again six times an hour.

The new read-only `GET git/matching-refs/heads/intake/` is checked against the legacy branch/PR listing. Only a **nonempty, structurally valid, consistent** inventory proves an absent exact intake ref and suppresses the per-binding negative probes. If matching refs are unavailable (empty/404) or disagree with legacy discovery, preserve the previous conservative branch/PR and per-binding fallback. A malformed inventory is a fail-closed error; it must not establish absence. Rate-limit 403 or other permission failure **must not** be interpreted as a missing branch. The existing bounded per-branch source, receipt, checksum, and PR-admission verifiers stay intact.

For administrative completion synchronization, the previous version performed an identical `GET actions/runs?head_sha=...&event=push` **twice** after both required workflows succeeded: once in its waiting gate and once in the underlying synchronizer. The candidate caches just the exact `{repository, head, successful run IDs}` within the single invocation and verifies those identities on reuse, saving one installation API read per successful synchronization invocation. If either required workflow has not succeeded, synchronization still stops without mutation and records its waiting state. The original protected ancestry, state and mirror validation remains active.

**Expected API impact for the measured snapshot:** successful nonempty matching refs + consistent branch/PR listing replace 20 redundant binding probes with one inventory read, yielding **19 fewer REST reads per ten-minute intake invocation**, approximately **114 fewer reads per hour if six equivalent invocations occur**. This is a counterfactual, not a live postmerge measurement. The synchronization change eliminates one redundant read per full-qualified invocation. No GraphQL is added.

## Separately governed GH-OS correction — not authorized by this PR

`ghos-routing-enforcement.yml` is a protected self-enforcing workflow. Its prequeue controller expressly rejects candidate modification of itself (`Reject enforcement self-modification`), and current GH-OS admission policy is pinned independently in `grandchallenge/.github`. **Do not** place a change to this workflow in an ordinary PR or bypass the protected gate. A specific control-plane authorization and policy-coordinated update is required. Proposed safe correction:

- Record exact PR head/base and whether native merge has stabilized, with typed statuses `CURRENT`, `SUPERSEDED`, and `NOT_YET_MATERIALIZED`. Treat `SUPERSEDED` as a retryable non-authority result, never publish a false successful required status.
- Deduplicate refresh requests against exact `(PR number, head SHA, protected base SHA)` and an existing **successful** required status for that exact tuple, rather than simply checking the PR head's historic status.
- Preserve protected base freshness, exact PR head parent match, external pinned GH-OS policy gate, native merge-group replay and required `routing-enforcement` status. Unknown identities continue fail closed.
- Before control-plane admission, fault-inject rapidly advancing base, temporarily missing `refs/pull/N/merge`, API merge lag, branch force push, stale job and 403/429. Require exact-head merge-group CI and authenticated protected readback.

**Governance boundary:** protected GH-OS workflow self-modification and the externally pinned admission policy cannot be changed through the ordinary engineering PR. No protected-state rule, required status, independent controller, or review authority is weakened in the ordinary candidate. Any remaining GH-OS revalidation storm needs that separately governed amendment.
