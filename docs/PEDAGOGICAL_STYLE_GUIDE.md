# Pedagogical Style Guide

## Purpose

Grand Challenge pedagogy is not simplification. It is structural revelation.

The goal is to let a serious reader see what the object is, why it resists proof, which claims are supported, and what the next honest move should be.

## Voice

Use a voice that is:

- lucid;
- exact;
- generous to the reader;
- severe with unsupported claims;
- comfortable with partial progress;
- allergic to performance.

Avoid language that sounds like marketing, mysticism, or victory before certification.

## The four-layer exposition pattern

### 1. Plain object

Begin with the object in ordinary mathematical language. Do not begin with machinery unless the machinery is the object.

Good opening question:

> What are we actually trying to understand?

### 2. Working model

Give a small example, toy case, picture, finite enumeration, or local model. The reader should be able to touch the object before encountering the full abstraction.

### 3. Formal spine

Introduce definitions, propositions, lemmas, and exact hypotheses. Each formal item should explain its role.

A lemma without a role is a loose gear.

### 4. Claim boundary

Mark status explicitly: proof, computation, conjecture, literature-derived assertion, failed attempt, or certification target.

## Required explanatory moves

A serious Work Package should explain:

- why this definition is the right definition;
- what examples it admits and excludes;
- what invariant is being preserved;
- where naive approaches fail;
- which finite computations are sanity checks rather than proof;
- what the formalization would need;
- what would change the claim status.

## Decorative discipline

Decoration is welcome when it teaches. Diagrams, tables, callouts, analogies, and names are useful if they compress structure.

Decoration is harmful when it hides uncertainty or substitutes atmosphere for content.

Use ornament as a lantern, not a curtain.

## Sentence-level guidance

Prefer:

> This computation verifies the finite cases up to size 4 and checks that our definitions behave as expected.

Avoid:

> This computation provides strong evidence for the conjecture.

Prefer:

> The obstruction is not enumeration; it is the lack of a monotone quantity that survives arbitrary unions.

Avoid:

> The problem is challenging and important.

Prefer:

> This lemma is useful because it converts the informal singleton argument into an injective counting statement.

Avoid:

> We prove a useful lemma.

## The final paragraph test

The final paragraph of every Work Package should answer:

1. What did we clarify?
2. What remains unproved?
3. What exact artifact should be built next?
4. What would promote the strongest claim in the ledger?
